Why Is It Needed?

New security threats created by multi-agent environments connected to external LLMs

Multi-agent systems connected to external LLMs such as ChatGPT, Claude, and Gemini are being adopted across enterprise operations. However, because agents process large volumes of data and execute tools far faster than people, a single security vulnerability can cause critical damage to the entire system.

Prompt Injection & Jailbreak

Maliciously crafted inputs alter agent behavior or neutralize system prompts. In multi-agent environments, the infection of one agent can spread in a chain reaction.

Confidential Information Leakage

Customer personal data, trade secrets, and internal documents are sent to external AI service APIs, unintentionally exposing corporate secrets.

Unauthorized Agent Infiltration

Unverified external agents may join internal orchestration systems, and messages from untrusted agents may be forged or tampered with.

Harmful / Hallucinated Output and Policy Violations

Harmful content, false information (hallucinations), and regulation-violating responses generated by AI agents propagate automatically to downstream systems and lead to real damage.

TMAF's five anomaly detection areas — monitoring the entire agent lifecycle

Input Anomaly Detection

  • Detects Prompt Injection attempts

  • Detects inputs containing sensitive information
  • Blocks policy-violating queries
Area 02

Output Anomaly Detection

  • Identifies harmful and hallucinated responses
  • Blocks regulation-violating content
  • Detects abnormal data combinations
Area 03

Behavior Anomaly Detection

  • Detects abnormal Tool Call sequences
  • Monitors excessive external API calls
  • Detects unauthorized data access
  • Baseline analysis of agent behavior patterns
Area 04

Communication Anomaly Detection

  • Detects unauthorized agent infiltration
  • Blocks calls to unregistered agents

Area 05

Execution Environment Anomaly Detection

  • Detects attempts to execute outside the protected area
  • Detects model theft and parameter extraction attempts
  • Continuously verifies execution environment integrity
  • Blocks license-violating execution

How Does It Protect?

TMAF's four security modules — going beyond detection to automated response

from TPA

Privacy Guard

Confidential information detection · substitution · pseudonymization · encryption

When connecting to external AI services, sensitive information is automatically detected and then pseudonymized or encrypted before transmission. Reverse conversion to restore the original information from AI responses is also supported, fully protecting confidential data while keeping workflows intact.

from TSA

Safety & Policy Guard

Prompt Injection / Jailbreak detection · harmful output blocking · policy decisions

At the input stage, prompt injection and Jailbreak attempts are detected and controlled in real time; at the output stage, harmful content and regulation-violating responses are blocked. A permission-based policy engine lets you define the allowed scope of actions for each agent in detail.

from DPF

Agent Trust Mesh

Agent authentication · unauthorized agent blocking · secure A2A communication

Every agent participating in a multi-agent system is registered and authenticated, and access by unauthenticated agents is blocked at the source. Signature verification of messages exchanged between agents ensures secure agent-to-agent communication free of forgery and tampering.

from CC-BOX

Confidential Runtime

TEE-based protected execution environment · model theft prevention · integrity verification

Sensitive agents run in an isolated environment based on a TEE (Trusted Execution Environment), fully protecting model parameters and processed data from the outside. Execution environment integrity is continuously verified remotely (Remote Attestation) to block theft attempts at the source.
